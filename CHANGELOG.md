## v0.8.0-rc — PROVISIONAL / UNRELEASED development notes

> Working-tree notes only. The prior private Round30 platform matrix was frozen
> with `v0.8.0-round30-dirty` at dirty HEAD
> `33701617cc782710092086714559aba45ddb441b`; it predates these Round31 doc
> edits. It is not a `v0.8.0-rc` tag or published release. Entries below
> describe development candidates, not a finished or supported release.

### Provisional features

- feat(billing): agent-side OCI cost collection via instance principal
  (`CP_OCI_BILLING=instance_principal`): an agent on an OCI instance runs
  `oci --auth instance_principal` itself and reports the tenancy's cost
  to the hub, for hubs that can't run the OCI CLI; Settings → Billing
  gains a step-by-step setup guide. See
  [billing.md](docs/billing.md#agent-side-oci-collection-instance-principal).
- feat(alerting): configurable warning/critical rule severity, snapshotted on each alert event; the seeded 95%/100% egress rules become critical to match their names (past events keep the severity they were delivered with)
- feat(channel-health): add per-channel health reporting from recent delivery
  outcomes and synthetic-test history, with an opt-in weekly synthetic check
  (off by default)
  and fallback dispatch through another healthy channel; the health API exposes
  a banner-needed state if none is available. This is a server/API note, not a
  Round31 UI change. The synthetic check sends a real test message when enabled;
  platform acceptance is not necessarily proof of recipient delivery. See
  [notifications.md](docs/notifications.md#health-report).
- feat(auth): audit dashboard password changes with non-secret outcome
  metadata; never record password/hash values or raw store errors. This is a
  provisional current-source change, not an independently reviewed security
  release claim.

### Provisional fixes

- fix(billing): OCI Usage API day bounds are computed in UTC; on a non-UTC
  host (e.g. KST) the end bound was sent as a non-midnight `T09:00:00Z`,
  which DAILY granularity rejects.
- fix(security): apply the existing security headers to CIDR-allowlist
  rejection responses as well as allowed routes, without changing CSP policy.
- fix(notifications): redact configured channel secrets and endpoint values
  from error-derived delivery and verification diagnostics before display or
  persistence, while retaining typed errors for classification.

### Development documentation

- docs: clarify public, agent-token, and dashboard API authentication;
  diagram the hub/data/integration flow; and add operational troubleshooting
  for empty/stale data, auth failures, and network-versus-browser diagnostics.

### Internal verification (not product features or release QA)

- Round30 local adapter tests recorded 26 focused / 766 package-suite pass
  events against guarded loopback recorders using synthetic credentials. This
  is a local adapter dry-run only: not provider acceptance, delivery, or
  end-to-end factory transport proof.
- Round30 platform evidence records 36 verifier tests, 12 private binaries and
  six report hashes, with limited native Linux/arm64 agent `-version`, agent
  `-once`, and hub `-version` checks. It is not a deployment candidate and
  includes no hub-server QA of a platform-matrix binary; other targets are
  static-only.
- Round30 recorded seven Compose-specimen static checks and a native README
  source smoke. The updated Round31 port-parameterized README block was also
  run offline against a disposable local source build. Docker/Compose
  config/build/up/health/down remain **NOT_EXECUTED**; neither source smoke is
  frozen-release-candidate or container QA.
- Existing traffic regressions recorded 23 top-level / 61 including-subtest
  passes for host accounting only. Per-process attribution remains DRAFT,
  deferred, and not implemented; those checks are not per-process feasibility
  evidence.
- Round30 parent docs/prepublish checks passed. That historical record contains
  nine accepted historical fixtures among nine detector matches and zero
  unresolved findings; zero unresolved does not mean zero detections. It does
  not certify later Round31 source changes; current checks are recorded separately.

These private checks and provisional notes are not release evidence, do not
establish live compatibility, and do not authorize publication or deployment.
